# 分类法与配置全字段

## 树形

```
<素材根>\
├─ .guicang\                  ← 配置 + 索引 + 人工判定（永远不扫描）
│   ├─ guicang.toml           库级配置
│   ├─ places.toml            地点清单
│   ├─ activities.toml        活动清单
│   ├─ manual.json            人工钉住的判定
│   └─ index.db               SQLite 索引（真相）
├─ _归藏\                      ← 分类树（永远不扫描）
│   ├─ 区域\<地点>\<年>\<年-月>\<拍摄类型>\<文件>
│   ├─ 活动\<活动>\<届次段>\<年-月>\<拍摄类型>\<文件>
│   └─ 待定\<年>\<年-月>\<拍摄类型>\<文件>
└─ <用户的原始目录>\...         ← 原件，一根手指都不碰
```

**为什么区域是单层。** 天天跑不出河南，套「省/市」两层只会多两层空目录。
第一层直接是具体地点（`郑州奥体中心`、`开封古城`、`洛阳老君山`），找东西时按地名想，
就是按第一层找。要加城市维度的话，把地点名写成 `郑州-奥体中心` 也能用，但没必要。

**届次段。** 活动枝的第三层叫「届次段」，取值规则：

| 情况 | 段 | 例 |
|---|---|---|
| 目录里写了「第39届」/「第十一届」 | `<年>-第N届` | `2026-第44届` |
| 没有届次 | 只写年份 | `2026` |
| 连时间都没有 | `未知时间` | `未知时间` |

届次只从**相对路径**里认（含文件名）。`第N届` 的数字支持阿拉伯数字与中文数字（十、十一、二十）。

## 时间粒度

`[time] depth`：

| depth | 形状 | 什么时候用 |
|---|---|---|
| `year` | `区域\开封古城\2026\航拍\` | 素材太多、月目录太碎 |
| `month` | `区域\开封古城\2026\2026-05\航拍\` | **默认**，航拍素材一般一个月一两场 |
| `day` | `区域\开封古城\2026\2026-05\2026-05-19\航拍\` | 同一天拍多场、需要按天找 |

改 depth 之后 `plan` 会给出新路径，`apply` 会把树按新结构再建一遍（旧的不会自动删，
要么 `undo` 上一轮，要么自己清 `_归藏\`；反正树只是链接，删了不掉原件）。

## guicang.toml 全字段

```toml
[library]
tree = "_归藏"            # 分类树目录名；改成别的名字也照样排除扫描

[time]
depth = "month"          # year | month | day

[region]
enabled = true           # 关掉后所有素材只走「活动 / 待定」两枝

[activity]
enabled = true           # 关掉后活动枝不建，活动命中也不影响落位

[web]
host = "127.0.0.1"       # 手机访问改 "0.0.0.0"
port = 8787
token = ""               # 空 = 谁都别进（绑定非回环地址时会自动生成一个并打印）

[sync]
backend = "local"        # local | s3

[sync.local]
dir = ""                 # 目标目录（网盘挂载点、移动硬盘都行）

[sync.s3]
endpoint = ""
region = "us-east-1"
bucket = ""
access_key = ""
secret_key = ""
prefix = "guicang/"
```

配置文件写坏（少引号、拼错）时 `load_config` 会**直接报错并指到行号**，不会静默退回默认值：

```
配置有问题：D:\素材\.guicang\places.toml 写得不对：Invalid statement (at line 1, column 1)
```

## places.toml

```toml
[[place]]
name = "开封古城"          # 出现的就是「区域」第一层目录名
aliases = ["开封", "清明上河园", "鼓楼"]   # 路径里出现就算命中
lat = 34.7978
lon = 114.3072
radius_km = 6.0           # GPS 吸附半径
```

- `radius_km` 给太小，GPS 差个 200 米就落进待定；给太大，相邻景点会互相抢。城区 2–4km、
  景区 6–10km 比较稳。
- `aliases` 要写**会出现在目录名的那个词**。天天的目录习惯是「2024-05-18 开封古城/城墙/」，
  所以 `开封` 这个别名就能命中。
- 同一张卡连拍同一地点时，GPS 精度可能到 ±50m，别把半径卡在 0.5km。

不知道坐标？在网页里挑一张那个地点的照片，`explain` 会打印它的 EXIF 经纬度，抄进清单即可。

## activities.toml

```toml
[[activity]]
name = "开封菊花文化节"
aliases = ["菊花节", "菊展", "菊花文化节"]
editions = []             # 可选：预留，暂不参与判定
```

- 别名要覆盖历年的叫法差异（「第39届菊花文化节」里有「菊花文化节」，加上就命中）。
- 只要路径里出现活动名或别名，置信度就到 0.75 以上；再加上届次，直接进活动枝。
- **同一个素材可能既在某地点又是某活动**。判据：活动置信 ≥ 0.7 → 进「活动」枝；
  否则进「区域」枝。活动枝优先，因为活动是一次性的、事后更想按活动找。

## 待定桶

进 `待定\` 的条件（任一）：

- 区域没认出来（没 GPS，路径里也没地名）
- 拍摄类型置信 < 0.75
- 区域置信 < 0.75
- 活动命中了但把握不足 0.7，同时区域也没认出来

每条待定都带一行原因，`report` 与 `review` 都会显示：

```
[7] 2025-01-08 随手拍/IMG_1001.JPG
    拍摄类型 地拍（0.80） · 区域 未识别（0.00）
    原因 地点没认出来：没有坐标，路径里也没出现清单上的地名
```

## 改判定

| 想改什么 | 改哪里 | 之后 |
|---|---|---|
| 地点名/坐标/半径/别名 | `places.toml` | `scan --force` |
| 活动名/别名 | `activities.toml` | `scan --force` |
| 时间粒度 | `guicang.toml` `[time] depth` | 直接 `plan` |
| 单条素材的判定 | `guicang review --set ...` | 自动重算那一条 |
| 树放哪 | `[library] tree` | 直接 `plan` |

`manual.json` 是人工判定的真相，格式：

```json
{
  "_说明": "guicang review --set 写在这里；命中即视为 1.0 置信，压过机器推断",
  "paths": {
    "2025-01-08 随手拍/IMG_1001.JPG": {"region": "开封古城", "shot_type": "地拍"}
  }
}
```

可以手改（路径用 `/` 分隔，相对素材根），改完 `scan` 就生效。手改坏了也只是那几条不生效，
不会让整库崩。
