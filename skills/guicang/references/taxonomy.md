# 分类法与配置全字段

## 树形

```
<素材根>\
├─ .guicang\                  ← 配置 + 索引 + 人工判定（永远不扫描）
│   ├─ guicang.toml           库级配置
│   ├─ places.toml            地点清单（含省/市/园区区域）
│   ├─ activities.toml        活动清单
│   ├─ manual.json            人工钉住的判定
│   └─ index.db               SQLite 索引（真相）
├─ _归藏\                      ← 分类树（永远不扫描）
│   ├─ 区域\<省?>\<市?>\<地点>\<园区区域?>\<年>\<周期>\<拍摄类型>\<机型?>\<文件>
│   ├─ 活动\<活动>\<届次段?>\<年>\<周期>\<拍摄类型>\<机型?>\<文件>
│   ├─ 抖音\<年>\<周期>\<拍摄类型 or 待定>\<机型?>\<文件>
│   └─ 待定\<年>\<周期>\<拍摄类型>\<文件>
└─ <用户的原始目录>\...         ← 原件，一根手指都不碰
```

带 `?` 的层都会**自动折叠**：那一层在库里只有一个取值时就不出现。

真实例子（demo 库就是照这个建的）：

```
区域\郑州\泡泡塘森林溪谷\水世界\2024\2024-05-18_05-24\航拍\DJI_0001.MP4
区域\郑州\泡泡塘森林溪谷\露营区\2024\2024-05-18_05-24\地拍\Canon EOS R5\IMG_8842.JPG
活动\开封菊花文化节\2024-第39届\2024\2024-07-06_07-12\航拍\DJI_0003.MP4
抖音\2024\2024-08-03_08-09\地拍\DY_0007.JPG
待定\2025\2025-01-04_01-10\地拍\IMG_1001.JPG
```

## 为什么是这个形状

**省/市/地点/园区区域 是一条真实的地理链。** 天天的说法是「河南 → 各地级市 → 泡泡塘森林溪谷（地点）
→ 园区里各区域 → 每次拍摄的时间 → 拍摄类型」。这套东西在 `places.toml` 里就是四个字段：

```toml
[[place]]
name = "泡泡塘森林溪谷"
province = "河南"
city = "郑州"
areas = ["水世界|水上乐园", "露营区", "花海"]
```

**折叠是硬规矩，不是可选项。** 库里只有郑州一个市，就没人想在每一层都看一遍「郑州」。
同理只有河南一个省时省不出现。`scan` 结束会打印「折叠掉的层级：省、市」，`plan` 里的路径是最终形状。
判断依据：只统计**区域枝**里自动归好的素材（活动枝的素材不进省市统计）。

**园区区域必须"认得出来"或"承认认不出来"。** `areas` 一写，等于承诺这里的素材能分到块；
认不出来不是随便扔个目录，而是进待定并说明原因（`review --set … --area 水世界` 钉一次就解决）。

**时间层 = 年 → 备份周期。** 天天的规矩原话：「每个周六为起始新日期，周五为结束日期」。
所以默认 `week`：先一年，再一个周期 `2024-05-18_05-24`。同一个月里 05-19（周日）和 05-18（周六）
同一个周期；跨年的周期（12-28 起的那个）整段留在起始年下面，不会被劈成两个年文件夹。
想按天/月/年归档改 `[time] depth`。

**抖音枝自成体系。** 路径里出现 `抖音` / `douyin` / `竖屏` 就整条归到 `抖音\`，不挂地点也不挂活动
（判定 0.90）。**不按画幅比例猜**——手机竖拍的日常素材不该全进抖音枝。拍摄类型没把握时，
最后一层写「待定」，仍然留在抖音里：剪辑打开抖音文件夹要能看见它，不是去根上的待定桶捞。

**机型层常开但几乎不落层。** `[layout] camera = true` 时，只有「同地点、同园区区域、同一个周期、同拍摄类型」
里真的出现了 ≥2 种机型，才在那下面多分一层机型；单一机型不分。读不到机型的那条会进 `未知机型\`。

**届次段。** 活动枝的第三层，取值规则：

| 情况 | 段 | 例 |
|---|---|---|
| 目录里写了「第39届」/「第十一届」 | `<年>-第N届` | `2026-第44届` |
| 没有届次 | **不出这一层**（年份由下一层给） | `活动\郑州马拉松\2025\2025-03-15_03-21\…` |
| 连时间都没有 | `未知时间` | `未知时间` |

最后一排是非直觉的那一条：届次退回年份时，时间层已经写过一次年，**届次层就不再重复**。

届次只从**相对路径**里认（含文件名）。`第N届` 的数字支持阿拉伯数字与中文数字（十、十一、二十）。

## 时间粒度

`[time] depth`：

| depth | 形状 | 什么时候用 |
|---|---|---|
| `year` | `区域\泡泡塘森林溪谷\水世界\2026\航拍\` | 素材太多、目录太碎 |
| `month` | `区域\泡泡塘森林溪谷\水世界\2026-05\航拍\` | 一个月一两场拍摄 |
| `day` | `区域\泡泡塘森林溪谷\水世界\2026-05-19\航拍\` | 要精确到拍摄当天 |
| `week` | `区域\泡泡塘森林溪谷\水世界\2026\2026-05-16_05-22\航拍\` | **默认**，备份周期（周六→周五） |

`week` 是**两层**：「年」+「周期」。年取周期**起点**的年——`2024-12-28_2025-01-03` 这个周期
整段挂在 `2024\` 下面，00:00 跨年也不劈开。

改 depth 之后 `plan` 会给出新路径，`apply` 会把树按新结构再建一遍（旧的不会自动删，
要么 `undo` 上一轮，要么自己清 `_归藏\`；反正树只是链接，删了不掉原件）。

## guicang.toml 全字段

```toml
[library]
tree = "_归藏"            # 分类树目录名；改成别的名字也照样排除扫描

[time]
depth = "week"           # week | day | month | year

[layout]
camera = true            # 机型层开关：同日同类型撞到 ≥2 机型才真的分层

[region]
enabled = true           # 关掉后所有素材只走「活动 / 待定」两枝

[activity]
enabled = true           # 关掉后活动枝不建，活动命中也不影响落位

[web]
host = "127.0.0.1"       # 手机访问改 "0.0.0.0"
port = 8787
token = ""               # 空 = 谁都别进（绑定非回环地址时会自动生成一个并打印）

[sync]
backend = "local"        # local | s3

[sync.local]
dir = ""                 # 目标目录（网盘挂载点、移动硬盘都行）

[sync.s3]
endpoint = ""
region = "us-east-1"
bucket = ""
access_key = ""
secret_key = ""
prefix = "guicang/"
```

配置文件写坏（少引号、拼错）时 `load_config` 会**直接报错并指到行号**，不会静默退回默认值：

```
配置有问题：D:\素材\.guicang\places.toml 写得不对：Invalid statement (at line 1, column 1)
```

## places.toml

```toml
[[place]]
name = "泡泡塘森林溪谷"      # 出现的就是「区域」里的地点目录名
aliases = ["泡泡塘", "溪谷"]  # 路径里出现就算命中
province = "河南"            # 可选；库里有 ≥2 个省时才出现在树里
city = "郑州"                # 可选；库里有 ≥2 个市时才出现在树里
areas = ["水世界|水上乐园", "露营区", "花海"]   # 可选；竖线左边是正式名
lat = 34.7412
lon = 113.7210
radius_km = 3.0              # GPS 吸附半径
```

- `radius_km` 给太小，GPS 差个 200 米就落进待定；给太大，相邻景点会互相抢。城区 2–4km、
  景区 6–10km 比较稳。
- `aliases` 要写**会出现在目录名的那个词**。天天的目录习惯是「2024-05-18 泡泡塘森林溪谷/水世界/」，
  所以 `泡泡塘` 这个别名就能命中。
- `areas` 写的是园区里真实的分区，别名用 `|` 隔开。写了就得在路径里认出来，否则待定。
- 同一张卡连拍同一地点时，GPS 精度可能到 ±50m，别把半径卡在 0.5km。

不知道坐标？在网页里挑一张那个地点的照片，`explain` 会打印它的 EXIF 经纬度，抄进清单即可。

## activities.toml

```toml
[[activity]]
name = "开封菊花文化节"
aliases = ["菊花节", "菊展", "菊花文化节"]
editions = []             # 可选：预留，暂不参与判定
```

- 别名要覆盖历年的叫法差异（「第39届菊花文化节」里有「菊花文化节」，加上就命中）。
- 只要路径里出现活动名或别名，置信度就到 0.75 以上；再加上届次，直接进活动枝。
- **同一个素材可能既在某地点又是某活动**。判据：活动置信 ≥ 0.7 → 进「活动」枝；
  否则进「区域」枝。活动枝优先，因为活动是一次性的、事后更想按活动找。

## 待定桶

进 `待定\` 的条件（按判定顺序，第一条命中的就是原因）：

- 区域没认出来（没 GPS，路径里也没地名）
- 拍摄类型置信 < 0.75
- 活动命中了但把握不足 0.75
- 区域置信 < 0.75
- 地点配了 `areas`，但路径里对不上是哪一块

**抖音枝是唯一例外**：它不要求区域，拍摄类型没把握时留在 `抖音\…\待定\`，
不进根上的待定桶——剪辑打开抖音文件夹得能看见它。

每条待定都带一行原因，`report` 与 `review` 都会显示：

```
[7] 2025-01-08 随手拍/IMG_1001.JPG
    拍摄类型 地拍（0.80） · 区域 未识别（0.00）
    原因 地点没认出来：没有坐标，路径里也没出现清单上的地名
```

## 改判定

| 想改什么 | 改哪里 | 之后 |
|---|---|---|
| 地点名/省/市/园区区域/坐标/半径/别名 | `places.toml` | `scan --force` |
| 活动名/别名 | `activities.toml` | `scan --force` |
| 时间粒度 | `guicang.toml` `[time] depth` | 直接 `plan` |
| 机型层 | `guicang.toml` `[layout] camera` | 直接 `plan` |
| 单条素材的判定 | `guicang review --set ... [--area ...] [--branch ...]` | 自动重算那一条 |
| 树放哪 | `[library] tree` | 直接 `plan` |
| 备份到网盘 | 工具不管，`_归藏\` 整包传上去 | — |

`manual.json` 是人工判定的真相，格式：

```json
{
  "_说明": "guicang review --set 写在这里；命中即视为 1.0 置信，压过机器推断",
  "paths": {
    "2025-01-08 随手拍/IMG_1001.JPG": {"region": "泡泡塘森林溪谷", "area": "水世界", "shot_type": "地拍"},
    "2024-08-03 泡泡塘/抖音竖屏/DJI_0008.MP4": {"branch": "抖音", "shot_type": "航拍"}
  }
}
```

可以手改（路径用 `/` 分隔，相对素材根），改完 `scan` 就生效。手改坏了也只是那几条不生效，
不会让整库崩。
